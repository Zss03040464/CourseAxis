# 验收清单

## A. 真实作息导入

准备学校课表“表格”视图，其中第 1 节明确显示 `08:00–08:40`，第 2 节明确显示实际时间。

```text
□ 导入预览显示已提取的节次数量。
□ 第 1–2 节课程解析为第 1 节开始、第 2 节结束。
□ 中间课间不会被当作上课分钟，但课程块跨越完整起止区间。
□ 不存在的节次不会使用内置默认时间。
□ 删除或清空作息后，SECTION_RULE 课程变为待确认，而不是保留旧时间。
```

## B. 用户核心痛点复现

新增单次事件：

```text
日期：考试周任意一天
时间：16:00–18:00
节次元数据：可由反查得到；即使旧数据写成 1–1 也不参与布局
```

验收：

```text
□ 周视图课程块顶部位于 16:00。
□ 课程块高度对应 120 分钟。
□ 不会跑到第 1 节所在位置。
```

## C. 考试

```text
□ 教务考试接口有数据时，导入预览显示考试数量。
□ 考试为 SINGLE，有明确自然日期。
□ 考试不依赖周次和节次。
□ Android/macOS 主界面和小组件均可显示考试。
□ 座位号进入备注，地点和校区保留。
```

## D. 冲突

创建：

```text
事件 A：16:00–18:00
事件 B：17:30–19:00
```

```text
□ 保存 B 时提示重叠 30 分钟。
□ 用户可取消或仍然保存。
□ 保存后周视图两项并排，不覆盖、不丢失。
□ 18:00–19:00 与 19:00–20:00 不提示冲突。
```

## E. 周次与日期

```text
□ 1-17周(单) 解析为 1,3,5,...,17。
□ 离散周 1-15周,17-18周 正确。
□ 第 1 周周一对应设置中的 firstWeekMonday。
□ 选中第 18 周时日期正确。
□ 超出 1–40 的异常周次被拒绝或忽略，不崩溃。
```

## F. 重导入

```text
□ 同一教务记录不会重复新增。
□ 教务中消失的记录被删除并生成 tombstone。
□ 用户手动改过真实时间的同 ID 课程不会被重导入覆盖。
□ 新导入没有作息时，旧学期作息不会继续误用。
```

## G. 小组件

Android：

```text
□ 小尺寸显示正在进行或下一项。
□ 文档修改后立即刷新。
□ 事件开始/结束边界后内容切换。
□ 点击小组件打开主应用。
```

macOS：

```text
□ 小/中/大尺寸均可添加。
□ App Group 数据可见。
□ 当前事件、下一项、今日列表正确。
□ 主应用保存后 WidgetCenter 刷新。
```

## H. 同步

```text
□ 空服务器第一次同步建立 revision 1。
□ Android 新增事件后同步，macOS 可拉取。
□ macOS 删除后同步，Android 删除传播。
□ 两端离线同时修改不同事件，恢复网络后都保留。
□ 同一事件同时修改时，updatedAt 较新的版本胜出。
□ 409 revision conflict 自动重试。
□ 公网 HTTP 地址被客户端拒绝。
```

## I. 数据可靠性

```text
□ JSON 导出可通过 schema/schedule.schema.json。
□ 损坏 JSON 导入时给出错误，不覆盖当前数据。
□ macOS 保存前保留上一份 backup JSON。
□ Android 原子临时文件写入失败时不留下半文件。
□ 服务端备份恢复后 revision 和文档完整。
```

## K. 周投影与用户学期日期

```text
□ 第 1 周可看到只在第 8 周发生的课程，课程块标记“非本周”并使用虚线弱化。
□ 第 8 周该课程恢复为实色，不再标记“非本周”。
□ 考试提醒和 Widget 在第 1 周不会包含第 8 周课程。
□ 修改第一周日期后重新导入，不产生重复学期、不覆盖用户日期。
□ 语义相同的旧学期会合并，课程、考试和作息引用全部重写到唯一学期。
```

## L. 恢复、考试与提醒

```text
□ 单项和批量删除后可以恢复上一次删除。
□ 重启应用后恢复入口仍然存在。
□ 周课表切到“考试”后按日期和时间显示考试名称、地点。
□ 只有用户点击启用时才请求通知权限。
□ 考试提醒按真实考试时间安排，不使用节次或非本周投影。
□ Widget 的跨日下一项显示“明天”或具体日期，隐私模式隐藏课程名和地点。
```

## M. 周卡片信息与未来最近项

```text
□ 周课表课程块直接显示教师与完整周次，不需要点开详情。
□ 缺失教师显示“教师待确认”，单双周显示为“1-17周（单）”等紧凑文案。
□ 今天完全无课时，小、中、大 macOS Widget 均显示未来最近真实事件。
□ 最近事件可超过 35 天并跨越学期边界。
□ 非本周投影仍不进入 Widget 和提醒。
```

## N. 桌面 Widget 未来课程数量

```text
□ 旧课程文档没有 widgetUpcomingCount 时默认使用 3，保存后可无损往返。
□ 设置页可将桌面未来课程数量调为 1–5，越界 JSON 被拒绝且不覆盖现有数据。
□ 当前课程优先；当天稍后课程与跨日未来课程按真实时间补足剩余位置。
□ 小、中、大尺寸分别最多显示 1、3、5 项，设置值大于尺寸容量时不压缩字体。
□ 中、大尺寸未来课程行显示日期、起止时间、课程名、地点和教师。
□ 隐私模式隐藏课程名、地点和教师，考试强调和非本周投影隔离规则保持不变。
□ 保存设置后 Widget 时间线立即刷新，重启应用后设置仍然存在。
```

## O. 统一周课表与安全教务会话

```text
□ macOS 侧边栏只包含周课表、教务导入、设置，启动和未知深链均进入周课表。
□ Android 与 macOS 周课表均提供“全部 / 课程 / 考试”，默认选择“全部”。
□ 考试使用暖色卡片并显示真实日期、开始、结束、名称和地点。
□ 点击课程或考试直接打开该事件编辑页，不再依赖课程管理或考试中心。
□ Android 教务页首屏不展开账号和学期大表单，学校登录页拥有主要可视空间。
□ 账号密码只以 Android Keystore AES-256-GCM 密文保存在私有偏好中，不进入课程 JSON、同步和备份。
□ 登录页没有验证码时，失效会话最多自动提交一次，并调用学校页面登录按钮。
□ 验证码可见时只填账号密码、聚焦验证码，不自动识别或提交。
□ 用户清除账号后密文和内存中的密码状态被清空，恢复为手动登录。
```

## P. Provider 与学期隔离

```text
□ Catalog 拒绝重复 Provider ID、重复会话 UUID、未知 Adapter、HTTP、通配域名和路径越界。
□ Android 每个 Provider 使用独立 Keystore 命名空间；支持 Multi-Profile 时 Cookie 和 WebStorage 不互通。
□ 不支持 Multi-Profile 的 WebView 在切换学校前清空默认会话，不声称可同时保留多学校登录。
□ macOS 每个 Provider 使用独立持久 WKWebsiteDataStore，清除当前学校不影响其他学校。
□ 相同学年学期在不同 Provider 下具有不同 term ID，课程、考试、作息和 Stable ID 不跨学校合并。
□ 选择学校时只激活该 Provider 的学期，切到“考试”不会跳回其他学期。
□ APK 和 .app 内的 Catalog、Provider 与 Adapter 与源码逐字节一致。
```

## Q. 公开候选与发行边界

```text
□ 公开候选树通过 public hygiene，不含真实课程、账号、Cookie、Token、本机路径、设备证据和内部过程文件。
□ 所有样例和 Provider fixture 由完全合成数据构成，Schema 和领域校验均通过。
□ 所有 workflow 外部 Action 固定到 40 位源码提交 SHA，actionlint、YAML 解析、CodeQL 和依赖审查通过。
□ fresh clone 可按 README 运行验证与无签名构建，工作树不产生未记录源码差异。
□ GitHub 候选在私有状态先跑完 CI；main 的 required checks、线性历史和禁止 force push 规则已配置。
□ Android APK 与 macOS 制品由本地发布流程签名/公证并验签，公开哈希与实际文件一致。
□ 公开仓库不包含签名私钥、JKS、证书、公证凭据或支付私有配置。
□ 未获得最终明确授权前，不创建公开远程、不 push、不发布 Release。
```
